`repos.json`, en la raíz de ronin (o donde diga `REPOS_CONFIG_PATH`), lista los repos que supervisa el runner. Va en `.gitignore`: nunca se commitea. Casi todo lo que no son rutas también se cambia desde [Ajustes → Repos](/ronin/operar/ajustes/#administración), que valida el archivo antes de escribirlo y guarda una copia del anterior.

```json
[
  {
    "productRepo": "acme/tienda",
    "productRepoPath": "/srv/repos/tienda",
    "claudeConfigDir": "/home/ronin/.claude-acme",
    "worktreeBaseRef": "origin/main",
    "explore": ["backoffice"],
    "linear": { "apiKeyEnv": "LINEAR_API_KEY_ACME" },
    "portal": {
      "name": "Acme",
      "apps": { "backoffice": { "name": "Backoffice", "description": "Pedidos, clientes y catálogo" } }
    },
    "deploy": { "selective": true },
    "apiFallback": { "apiKeyEnv": "ANTHROPIC_API_KEY_ACME", "model": "sonnet", "maxUsd": 30 }
  }
]
```

## Campos

| Campo | Qué es |
|---|---|
| `productRepo` | `owner/repo` en GitHub. **Obligatorio.** |
| `productRepoPath` | Un clon local del repo, hecho a mano. ronin nunca lo clona: hace fetch y crea worktrees al lado. **Obligatorio.** |
| `claudeConfigDir` | La carpeta de config de Claude Code con la que corren los agentes de este repo, si es una cuenta distinta de la global (`CLAUDE_CONFIG_DIR`). |
| `worktreeBaseRef` | La rama base, si no es `origin/main` (por ejemplo `origin/odoo-main`). Sin esto, todo lo que depende de la base (specs, stacks, merges) va contra la rama equivocada. |
| `concurrency` | Cuántas tareas de este repo corren a la vez. Por defecto, `TICK_CONCURRENCY`. Cada repo tiene su propia cola. |
| `autoMerge` | `false` para que los PRs de slice salgan sin `ronin:auto-merge` y los mergee una persona. |
| `explore` | Las apps de `ronin.app.json` que se [exploran](/ronin/guias/explorar-una-app/): aparecen en Exploraciones, con «Explorar ahora», y se exploran de noche. |
| `exploreNightlyOff` | Las apps de `explore` que no se exploran de noche. Siguen en Exploraciones y se exploran solo a mano. |
| `knowledge` | La [bitácora](/ronin/guias/pedidos-del-portal/#la-bitácora-de-cada-app) de cada app. `portalOff`: las apps cuyos pedidos no la usan (sin esto, la usan todas). `previews`: las apps cuyas previews la usan (sin esto, ninguna). |
| `agent` | Modelo y esfuerzo para la cuenta de este repo: `model`, `effort`, y por tipo de tarea `models` y `efforts` (por ejemplo `{ "external-review": "opus" }`), más `reviewWorkerModel`. Ganan sobre las variables de entorno. |
| `linear` | `apiKeyEnv`: el nombre de la variable de `.env` con la key de Linear del workspace. `explorationProject`: app → proyecto donde van los issues de su exploración. Ver [Linear](/ronin/operar/linear/). |
| `portal` | El repo en el [portal de pedidos](/ronin/operar/portal/): `name` (como lo ve la gente), `apps` (las claves son las de `ronin.app.json`, con `name` y `description`) y `notifyTo` (correos de respaldo del equipo). |
| `deploy` | Que se pueda [desplegar](/ronin/guias/desplegar/) desde el tablero: `prerelease`, `selective` y `auto` (los pedidos del portal se despliegan solos, con el patrón de su tag: `{ "tag": "v{major}.{minor}.{patch+1}" }`). |
| `apiFallback` | Terminar con una API key de la consola de Anthropic la corrida que la cuota de la suscripción cortó a mitad de camino: `apiKeyEnv` (la variable de `.env` con la key), `model` (por defecto `sonnet`) y `maxUsd` (el tope de gasto, obligatorio). Ver [Respaldo por API](#respaldo-por-api). |
| `changelogRepo`, `changelogRepoPath` | Publicar una entrada en un repo de changelog con cada release. Van juntos. Ver [Changelog](/ronin/operar/changelog/). |

<Aside type="note">
Agregar o quitar un repo, y cambiar sus rutas, se hace en el archivo. Después de agregar uno, corré `pnpm init-labels` y, con el servidor, `pnpm init-webhooks <url>`.
</Aside>

## Respaldo por API

Se configura en [Ajustes → Repos](/ronin/operar/ajustes/#administración): se elige la variable de `.env` con la key (solo se listan las `ANTHROPIC_API_KEY_*`), el modelo y el tope, que empieza en $20. También se puede escribir a mano en el archivo.

Cuando la cuota de la suscripción de Claude se agota mientras un agente trabaja (arreglando los checks de un PR, por ejemplo), la corrida se corta. Sin `apiFallback`, la tarea espera a que vuelva la cuota. Con `apiFallback`, ronin la retoma en el momento con la API key del repo:

- **Sigue en la misma sesión,** con `claude --resume`: el agente conserva lo que ya hizo y leyó. Si la sesión no está, empieza la tarea de nuevo con la key.
- **En el modelo del respaldo,** más barato que el de las corridas normales.
- **Con lo que le queda al repo** como `--max-budget-usd`. Claude Code lo revisa al terminar cada turno, así que una corrida puede pasarse un poco. Con menos de $0,50 de saldo, la corrida espera a la cuota como antes.
- **Solo lo que se cortó:** una tarea que no llegó a empezar porque la cuota ya estaba agotada no arranca por API, espera.

Lo que gasta cada repo por API se ve en [Ajustes → Cuentas de Claude](/ronin/operar/ajustes/#administración). El contador se reinicia ahí, después de recargar los créditos de la key. Al pasar el 80 % del tope, el repo aparece en la barra de abajo del tablero.

<Aside type="caution">
La key va en `.env` con un nombre `ANTHROPIC_API_KEY_<REPO>` (una variable nueva aparece en Ajustes después de desplegar), nunca en `repos.json` y nunca como `ANTHROPIC_API_KEY`: con ese nombre todas las corridas cobrarían a la API. Créala en un workspace propio de la consola, con un límite de gasto: es el tope que se cumple aunque ronin cuente mal (no cuenta, por ejemplo, una corrida que se cortó por tiempo).
</Aside>
