Un PR que abrió ronin se decide leyendo su descripción, no recorriendo el diff línea por línea. Siempre tiene las mismas secciones, y la pestaña **Descripción** del tablero las muestra por separado. Si le pedís un ajuste y cambia el código, ronin también pone al día la descripción, para que siga contando el PR como está:

| Sección | Qué dice |
|---|---|
| **Qué se pidió** | El pedido, con sus palabras. |
| **Qué cambió** | El cambio, con capturas cuando se ve. |
| **Cómo se verificó** | Lo que probó y lo que no. Al final, plegado, **Cómo probar**: los datos que hacen falta y los pasos para probarlo, con qué rol, en qué pantalla y qué se debería ver. |
| **Decisiones propias** | Lo que el pedido no definía y ronin decidió por su cuenta, con el porqué. |
| **Preguntas** | Solo si su review interna dejó un bloqueo real, algo que tiene que decidir una persona. El tablero las pone arriba de la ficha (ver [Las preguntas](#las-preguntas)); mientras quede alguna, el auto-merge espera. |
| **Fuera de alcance** | Lo que vio y dejó para otro PR. |

![La pestaña del PR en el tablero, con la descripción por secciones y las decisiones propias destacadas](../../../assets/capturas/pr-descripcion.png)

<Aside type="tip" title="Lo que más vale mirar">
Las **decisiones propias** van destacadas. Si una no te convence, es lo primero que conviene ajustar.
</Aside>

## Las preguntas

Si la descripción tiene preguntas, la ficha las muestra debajo del encabezado, en todas las pestañas, con las respuestas que sugiere ronin como botones. Elegís una, o **Otra respuesta** para escribir la tuya, y **Mandar** se las pasa a ronin directo, como un pedido bajo la actividad del ítem (en el PR de un spec, comentadas en GitHub mencionando a ronin). ronin aplica las respuestas, saca las preguntas y, con el commit nuevo, vuelve a pasar la review interna.

No hace falta contestarlas todas a la vez: las que no respondiste quedan. Mientras quede alguna, el PR no se mergea solo, aunque lo apruebes: **Aprobar** te lo avisa.

## Las tres decisiones

Están en el encabezado de la ficha, en todas las pestañas. Cada una se despliega debajo del botón y te dice qué se va a mandar, a tu nombre, antes de mandarlo.

<CardGrid>
  <Card title="Aprobar · A" icon="approve-check-circle">
    Aprueba el PR y le pide el auto-merge a ronin, que lo mergea cuando pasen los checks. Si ya tiene auto-merge o tiene conflictos, solo aprueba. Si quedan preguntas, te avisa que no se va a mergear hasta que las contestes. `↵` confirma.
  </Card>
  <Card title="Ajustar · P" icon="pencil">
    Escribís qué debería cambiar y se lo pedís a ronin directo, sin un comentario en GitHub: empieza en ese momento, y el pedido y su respuesta quedan bajo la actividad del ítem, a la vista de todos. `Ctrl ↵` manda.
  </Card>
  <Card title="Cerrar · X" icon="close">
    Un motivo opcional, que queda como comentario, y el PR cerrado. **Cerrar también el issue** viene marcado. `Ctrl ↵` confirma. Si el PR es de un [pedido del portal](/ronin/guias/pedidos-del-portal/) y cerrás también el issue, el motivo le llega a quien lo pidió, tal cual, en la conversación y por correo.
  </Card>
</CardGrid>

![Ajustar desplegado: el texto del ajuste, las frases rápidas y lo que se va a comentar](../../../assets/capturas/ajustar.png)

Lo que decidís se ve en el momento, sin esperar a GitHub: el panel se cierra, la ficha dice *Aprobando el PR…* (o *Cerrando*, o *Mandándole el ajuste*) y los tres botones quedan en espera hasta que GitHub lo confirma. Al aprobar, el PR ya figura *aprobado* en la ficha y en la lista. Si GitHub no lo toma, se deshace y el panel vuelve con lo que habías escrito y el motivo.

<Aside type="caution">
Si cerrás el PR y dejás el issue abierto, ronin lo bloquea y te avisa: se queda sin PR para seguir.
</Aside>

## Ajustar con comentarios en líneas

En un PR de ronin, la pestaña **Archivos** sirve para comentar líneas, pero no tiene **Terminar revisión**: tus comentarios pendientes los lleva **Ajustar**, y la barra dice cuántos hay. Al mandarlo, se manda tu revisión y después `@ronin-agent /fix-comments` con tu texto.

Mientras escribís, el texto no se pierde con los refrescos del tablero. Con el foco fuera del texto:

| Tecla | Qué hace |
|---|---|
| `1`–`3` | Suma una frase rápida al ajuste |
| `I` | Marca o desmarca *Cerrar también el issue* |
| `Ctrl ↵` | Manda |

En el PR de un spec que escribió ronin (`/spec`), la barra cambia un poco: **Aprobar** no pide el auto-merge, porque aprobarlo es la señal para que ronin lo mergee y arranque las slices. **Ajustar** con comentarios de Archivos los manda como una revisión que menciona a ronin, que cambia el spec en un commit nuevo y contesta. **Cerrar** deja el issue como estaba. Ver [Un spec que escribió ronin](/ronin/guias/darle-trabajo/#un-spec-que-escribió-ronin).
